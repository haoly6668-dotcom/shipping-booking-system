# 数据库备份与恢复

在项目目录使用有权限的 Windows 账号运行：

```powershell
.\.venv\Scripts\python.exe scripts/backup_database.py --server localhost --database HarborBooking --verify-restore
```

脚本创建带时间戳的新备份，执行 `COPY_ONLY`、`CHECKSUM` 与 `RESTORE VERIFYONLY`，随后恢复到新建的 `HarborBooking_RestoreCheck_时间戳` 验证库，比较业务表行数及 TEU、重量汇总。现有库和文件不覆盖，不使用 `WITH REPLACE`。验证库保留供 SSMS 检查，后续由使用者确认不再需要后管理。

备份写入项目 `backups/`。脚本面向本机 SQL Server；数据库服务账号需要对此目录有写入权限。如果电脑使用了严格的目录权限，由管理员只为该备份目录授予 SQL Server 服务账号必要权限，不要开放整个磁盘。远程实例请在服务器运行备份并取回文件。实际结果保存在 `docs/backup-verification.json`。

本机生成的 `.bak` 来自 SQL Server 2025，不能还原到更旧的 SQL Server。其它电脑优先用 `setup.ps1` 和源 SQL 脚本重建模拟数据。还原真实修改后的数据时，需要同版或更新版 SQL Server，使用 SSMS 选择新的数据库名称和新数据文件路径，不覆盖现有业务库。

数据库备份不等于整个应用配置备份。数据库运行账号是服务器级登录；在另一实例恢复后，需要由数据库管理员新建受限登录并映射用户，按 `scripts/setup_database.py` 的逐对象授权方式授权，然后将连接串填入自己的 `.env`。不要把数据库账号赋予 db_owner 或直接使用 sa 运行网页。

`.env` 包含本机随机密钥与数据库口令，不进入源码压缩包；演示网页登录账号与数据库登录账号相互独立。
